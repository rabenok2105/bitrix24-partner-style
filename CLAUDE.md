# Инструкции для агента (Claude Code)

Ты работаешь внутри git-репозитория, который **одновременно является установленным
скиллом** `bitrix24-partner-style` (папка `~/.claude/skills/bitrix24-partner-style`).
Любая правка здесь меняет общий командный скилл. Поэтому строго следуй правилам ниже.

## Golden rule: НЕ коммить и НЕ пушь в `main` напрямую

Все изменения вносятся **через отдельную ветку и Pull Request**. Прямой commit/push
в `main` запрещён командным соглашением (технической блокировки нет — тем важнее не
нарушать). Стандартный цикл:

```bash
git checkout main && git pull            # свежий старт
git checkout -b feature/kratkoe-opisanie # ветка под задачу
# ...вносишь правки...
git add -A
git commit -m "Что изменил и зачем"
git push -u origin feature/kratkoe-opisanie
gh pr create --fill                      # открыть PR
```

**Перед `gh pr create` и любым `push` — сообщи человеку, что собираешься открыть PR /
запушить ветку, и дождись подтверждения.** Открытие PR и push — действия наружу.

## Что и где менять

- **Правила стиля и поведение скилла** → `SKILL.md`.
- **Вёрстка и бренд-кит** → `assets/` (`bitrix24-kit.css`, `bitrix24-template.html`,
  `DESIGN_SYSTEM.md`, шрифты, логотипы, фото, иконки).
- Меняешь визуальное правило — почти всегда правь **`SKILL.md` и `assets/` вместе**,
  иначе описание и реализация разъедутся.
- Скрипт рендера — `scripts/render.py`.

## Пополнять бренд-кит — можно и нужно ✅

Добавлять **новые ассеты** в кит — это нормальный, желанный вклад (через PR).
Клади в правильную папку:

- **Фото людей** → `assets/bitrix24-images/people/` (png с прозрачным фоном / cutout).
- **Иконки** → `assets/bitrix24-images/icons/` (svg; если есть тёмная версия —
  добавляй парой `имя.svg` + `имя-white.svg`, как у существующих).
- **Логотипы** → `assets/bitrix24-logo/`.
- **Шрифты** → `assets/Montserrat (1)/`.

После добавления — **зарегистрируй ассет там, где скилл ведёт их каталог**
(`DESIGN_SYSTEM.md` и/или `SKILL.md`), иначе скилл не будет знать, что файл
появился, и не станет его использовать. Именуй в стиле существующих файлов.

## Чего НЕ делать

- ❌ **Не пиши абсолютные пути** в `SKILL.md`, `CLAUDE.md` и справочниках
  (`DESIGN_SYSTEM.md`, `ICONS.md`, `PEOPLE.md`, `LOCALIZATION.md`). Только пути
  **относительно корня репозитория** — `assets/DESIGN_SYSTEM.md`, `scripts/render.py`,
  `bitrix24-images/people/…`. Путь вида `/Users/<имя>/…` или `~/.claude/skills/…`
  работает только на одной машине: у коллеги, в форке и в CI он ведёт в никуда.
  Репо лежит там, где его склонировали, — не там, где оно лежит у тебя.

- ❌ **Не коммить сгенерированные выгрузки** — финальные файлы, которые скилл
  отрендерил под конкретную задачу (готовый `guide.pdf`, слайды `slide-01.png`
  и т.п.). Это результат работы скилла, а не сам скилл. Обычно скилл рендерит их
  в рабочую папку проекта, а не сюда; если такой файл всё же оказался в репо —
  не добавляй его в коммит. *(Речь именно о выгрузках, НЕ о новых ассетах кита —
  их добавлять нужно, см. раздел выше.)*
- ❌ **Не публикуй ассеты вовне** и не делай репозиторий публичным — это
  **приватные** внутренние материалы Bitrix24 Partners (логотипы, шрифт
  Montserrat, фото людей). «Не публиковать» = не выкладывать наружу; **внутри
  репо пополнять кит можно**.
- ❌ Не мержи свой PR сам без ревью владельца.
- ❌ Один PR = одно логическое изменение. Не сваливай несвязанные правки в кучу.

## Сетевой нюанс

`git push` / `git pull` / вызовы GitHub API у части команды **периодически рвутся**
(`SSL_ERROR_SYSCALL`, `EOF` к github.com) из-за VPN / антивируса с проверкой HTTPS.
Это не поломка — **повтори команду несколько раз**, обычно проходит с 2–7 попытки.
