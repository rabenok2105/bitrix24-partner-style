# Инструкции для агента (Claude Code)

Ты работаешь внутри git-репозитория, который **одновременно является установленным
скиллом** `bitrix24-partner-style` (папка `~/.claude/skills/bitrix24-partner-style`).
Любая правка здесь меняет общий командный скилл. Поэтому строго следуй правилам ниже.

## Golden rule: НЕ коммить и НЕ пушь в `main` напрямую

Все изменения вносятся **через отдельную ветку и Pull Request**. Прямой commit/push
в `main` запрещён командным соглашением (технической блокировки нет — тем важнее не
нарушать). Стандартный цикл:

```bash
git checkout main && git pull            # свежий старт
git checkout -b feature/kratkoe-opisanie # ветка под задачу
# ...вносишь правки...
git add -A
git commit -m "Что изменил и зачем"
git push -u origin feature/kratkoe-opisanie
gh pr create --fill                      # открыть PR
```

**Перед `gh pr create` и любым `push` — сообщи человеку, что собираешься открыть PR /
запушить ветку, и дождись подтверждения.** Открытие PR и push — действия наружу.

## Что и где менять

- **Правила стиля и поведение скилла** → `SKILL.md`.
- **Вёрстка и бренд-кит** → `assets/` (`bitrix24-kit.css`, `bitrix24-template.html`,
  `DESIGN_SYSTEM.md`, шрифты, логотипы, фото, иконки).
- Меняешь визуальное правило — почти всегда правь **`SKILL.md` и `assets/` вместе**,
  иначе описание и реализация разъедутся.
- Скрипт рендера — `scripts/render.py`.

## Чего НЕ делать

- ❌ Не коммить сгенерированные выгрузки (готовые `*.pdf`, `*.png`) — они в
  `.gitignore`. В репозитории только исходники скилла и бренд-кит.
- ❌ Не публикуй ассеты вовне и не делай репозиторий публичным — это **приватные**
  внутренние материалы Bitrix24 Partners (логотипы, шрифт Montserrat, фото людей).
- ❌ Не мержи свой PR сам без ревью владельца.
- ❌ Один PR = одно логическое изменение. Не сваливай несвязанные правки в кучу.

## Сетевой нюанс

`git push` / `git pull` / вызовы GitHub API у части команды **периодически рвутся**
(`SSL_ERROR_SYSCALL`, `EOF` к github.com) из-за VPN / антивируса с проверкой HTTPS.
Это не поломка — **повтори команду несколько раз**, обычно проходит с 2–7 попытки.
